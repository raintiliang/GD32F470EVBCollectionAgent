   - 线程安全设计（pthread_mutex_t）
   - 分级调试系统（ERROR/WARN/INFO/DEBUG）
   - 存根与真实 API 分离设计（USE_REAL_NETWORK_API）

2. **HAL 接口扩展（方案B）**：
   - 扩展 `app_hal.h` 添加完整网络类型定义
   - `hal_network_status_t` - 网络状态结构
   - `hal_netif_config_t` - 网络接口配置
   - `hal_wifi_config_t` - WiFi 配置
   - 统一使用 `hal_err_t` 类型，避免冲突

3. **编译问题修复**：
   - 添加 `#include <stdarg.h>` 修复 `va_start/va_end`
   - 使用 `snprintf` 替换 `strncpy` 修复字符串截断警告
   - Makefile 调整：网络测试程序不链接 IMP 库

### 🔍 问题诊断
4. **系统初始化架构问题定位**：
   - **根本原因**：`app_hal_common.c`（通用实现）和 `platform_ingenic.c`（平台实现）重复定义相同 HAL 函数
   - **现象**：网络初始化从未被调用（`g_network_priv.network_initialized` 始终为 false）
   - **调试结果**：平台层函数被通用层覆盖，链接器使用第一个遇到的符号

5. **架构修复方案**：
   - 实施分层初始化架构：
     - 通用 `hal_sys_init()` 调用平台特定 `platform_ingenic_sys_init()`
     - 重命名平台函数以避免重复定义
   - **新问题**：其他 HAL 函数（VI、音频、外设等）仍然存在重复定义冲突
